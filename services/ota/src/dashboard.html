止损设置

控制台设置优先于环境变量，重启后仍生效。

判定止损所需的最小样本数，默认 20。
口径：只统计「被本通道下发过当前版本」的设备（cohort）。启动失败看启动次数，安装失败看下载 / 应用次数； 任一信号达到该样本量才判定，否则显示「样本不足」，不会告警也不自动止血。
取值建议：按「一个评估窗口内预期检查更新的设备量级」设定。设太大可能永远凑不够样本（小车队 / 低流量）， 太小则容易被偶发回退等噪声误判。评估窗口由 OTA_STOP_LOSS_WINDOW_MS 控制，默认 30 分钟。
这里的值优先于环境变量 OTA_STOP_LOSS_MIN_SAMPLES，保存后立即生效并持久化。
支持钉钉 / 企业微信、飞书 / Lark、Slack 机器人地址，或任意接收 JSON 的 http(s) 地址。消息体会按平台自动适配：
钉钉 / 企业微信：https://oapi.dingtalk.com/robot/send?access_token=xxx、 https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
飞书：https://open.feishu.cn/open-apis/bot/v2/hook/xxx
通用 / Slack 收到 {"text":"...","payload":{...}}；钉钉/企微为 {"msgtype":"text","text":{"content":"..."}}；飞书为 {"msg_type":"text","content":{"text":"..."}}。

回收设置

控制台设置优先于环境变量，下一次定时回收即生效；这里只开放「保留天数」「最少保留版本数」和执行模式。

发布超过该天数的版本才可能被回收，默认 14，0 表示不按天数保留。
这个窗口是给「已经下载了旧 manifest、但还没开始拉资产」的设备留的缓冲：资产 URL 里带 releaseId， 目录删掉后这类请求会 404。建议不小于客户端的最长离线时间。
无论多老，最近 N 个版本一定保留，默认 10，下限 3（留出回滚与观察余量）。
与「保留天数」是并集：任一条件命中即保留。
注意：差分补丁需要最近若干版本作为 base，因此实际保留数不会少于 OTA_PATCH_MAX_BASES（默认 5）。设成 3 时，系统仍会保留 5 个， 上方会直接显示实际生效值。
自动回收需要在服务端启动时设置 OTA_GC_ENABLED=true，否则这里只能改保留策略， 真实回收只能走版本页的逐条「回收」或命令行 npm run ota:gc -- --apply。 切换为「执行」后，下一次定时任务就会按上面的策略删除目录。
不会被回收：各通道 current / previous 指针指向的版本，以及最近若干差分 base。
联动清理：引用已删版本的补丁索引条目会被移除，不再被引用的 .bsdiff 一并回收； 已注册的内置包（embedded/）不受影响。
不是撤回：CDN 已缓存的副本仍可访问，回收释放的是源站空间。
接口：/api/admin/state · /api/channels · /api/metrics
